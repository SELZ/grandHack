# ГрантХаб

Приложение с каталогом грантов, профилем бизнеса, избранным и помощником по подбору программ. Работает в обычном браузере и как мини-приложение MAX.

Для локальной проверки сайта токен MAX, учётная запись MAX, VPS и Docker не нужны. Frontend и backend запускаются на компьютере, SQLite создаётся автоматически.

## Требования

- Node.js 22.12 или новее и npm.
- Git для клонирования либо ZIP-архив репозитория.
- Интернет для установки зависимостей.

Версии можно проверить командами:

```sh
node --version
npm --version
```

Все команды ниже выполняются в терминале из корня проекта — папки с этим README и корневым `package.json`.

## Скачать проект

```sh
git clone https://github.com/SELZ/grandHack.git
cd grandHack
```

При скачивании ZIP распакуйте архив и откройте терминал в полученной папке.

## Первый локальный запуск

```sh
npm run setup
npm run install:all
npm run build
npm start
```

Что выполняют команды:

1. `setup` создаёт корневой `.env` из `.env.example` и генерирует случайные `JWT_SECRET` и `INTERNAL_API_KEY`. Существующий `.env` не перезаписывается.
2. `install:all` устанавливает зависимости frontend, backend и бота из lock-файлов. Сам бот при этом не запускается.
3. `build` собирает frontend и backend.
4. `start` запускает backend, который обслуживает API и собранный frontend.

Откройте в браузере:

- Сайт: http://127.0.0.1:4000
- Проверка API: http://127.0.0.1:4000/api/health — ожидаемый ответ `{"ok":true}`.

Терминал должен оставаться открытым, пока вы пользуетесь приложением. Для остановки нажмите `Ctrl+C`.

После установки и сборки для повторного запуска достаточно:

```sh
npm start
```

После изменения исходников перед `npm start` снова выполните `npm run build`.

## Режим разработки

Для работы с исходниками и автоматического обновления интерфейса используйте:

```sh
npm run dev
```

Перед первым запуском этого режима также нужны `npm run setup` и `npm run install:all`. Предварительная сборка не требуется.

Команда запускает frontend и backend вместе:

- Интерфейс: http://127.0.0.1:5173
- API: http://127.0.0.1:4000/api
- Проверка API: http://127.0.0.1:4000/api/health

Запросы frontend к `/api` проксируются на локальный backend. `Ctrl+C` останавливает оба процесса. Перед переключением между `npm run dev` и `npm start` остановите предыдущий запуск: оба режима используют порт backend `4000`.

## Проверить основной сценарий

1. Откройте сайт. Вход по логину и паролю не требуется: создаётся гостевая сессия браузера.
2. Нажмите «Все гранты», проверьте поиск, категории и фильтры. В новой базе доступны 34 программы.
3. Откройте карточку гранта и добавьте его в избранное.
4. Перейдите в «Профиль», заполните данные бизнеса и нажмите «Сохранить профиль».
5. Откройте «ИИ-помощник» и отправьте «Подбери мне гранты». Помощник использует каталог и профиль; отдельный ключ языковой модели не требуется.
6. Обновите страницу или перезапустите приложение. Профиль и избранное должны сохраниться.
7. Откройте сайт в другом профиле браузера или отдельном приватном окне: у него будут собственные профиль и избранное.

## Где сохраняются данные

Локальная база находится в `grants-backend/data/grants.db`. Отдельно устанавливать сервер базы данных не нужно. При первом запуске каталог загружается из `grants-backend/data/grants.seed.json`.

Пользователи, профили и избранное хранятся в SQLite и сохраняются после остановки приложения. Идентификатор гостевой сессии хранится в браузере. Очистка данных сайта лишает браузер доступа к прежней гостевой сессии, но не удаляет её записи из базы.

Для повторного входа в ту же гостевую сессию используйте тот же профиль браузера и тот же адрес. `localhost` и `127.0.0.1`, а также порты `5173` и `4000` имеют отдельное хранилище браузера и создают разные гостевые сессии. Аккаунт MAX и гостевая сессия сайта также независимы.

## Локальные настройки

Для стандартного запуска достаточно `.env`, созданного командой `npm run setup`. Значения токенов с сервера копировать не нужно.

| Переменная | Назначение и локальное значение |
| --- | --- |
| `NODE_ENV` | `development` для локального запуска, в том числе через `npm start` |
| `HOST` | `127.0.0.1` — приложение доступно на этом компьютере |
| `PORT` | Порт backend, по умолчанию `4000` |
| `JWT_SECRET` | Секрет подписи сессий; `setup` создаёт автоматически |
| `INTERNAL_API_KEY` | Ключ связи бота с backend; `setup` создаёт автоматически |
| `DB_PATH` | `data/grants.db`; относительный путь считается от `grants-backend` |
| `FRONTEND_DIST` | `../grants/dist` — каталог собранного frontend |
| `ALLOW_DEV_AUTH` | `true` разрешает отдельный локальный тестовый endpoint; браузер использует гостевую сессию |
| `NOTIFICATIONS_ENABLED` | `false` — отправка уведомлений выключена |
| `MAX_BOT_TOKEN` | Для проверки сайта оставьте пустым; нужен при подключении MAX |
| `MAX_BOT_USERNAME` | Имя своего бота без `@`, если подключаете MAX |
| `API_BASE_URL` | Адрес backend для бота, по умолчанию `http://127.0.0.1:4000` |
| `ALLOWED_ORIGINS` | Необязательный список разрешённых origins через запятую; стандартные локальные адреса уже разрешены |

После изменения `.env` перезапустите приложение. Секреты должны содержать не менее 32 символов. `.env`, `.env.production` и файлы локальной базы исключены из Git.

## Автоматические проверки

После установки зависимостей выполните:

```sh
npm run check
npm test
npm run build
```

`check` проверяет код frontend, backend и бота. `test` запускает тесты фильтрации, API и обработчиков бота; backend-тесты используют отдельную базу в памяти. Рабочий токен MAX для них не требуется, сообщения в MAX не отправляются.

## Если приложение не запускается

| Ситуация | Что проверить |
| --- | --- |
| Команда `node` или `npm` не найдена | Установите Node.js и заново откройте терминал |
| Установка сообщает о неподдерживаемой версии Node.js | Используйте Node.js 22.12 или новее, затем повторите `npm run install:all` |
| Не найдены зависимости, Vite или tsx | Выполните `npm run install:all` из корня проекта |
| Ошибка о `JWT_SECRET` или `INTERNAL_API_KEY` | Выполните `npm run setup`. Если `.env` уже существует с пустыми значениями, сохраните его под другим именем и повторите `setup` либо заполните оба секрета самостоятельно |
| `EADDRINUSE` или занят порт `5173` | Остановите предыдущую копию приложения или другой процесс, использующий этот порт |
| Порт backend `4000` занят | Остановите занимающий его процесс либо задайте, например, `PORT=4001` в `.env`. В режиме разработки прокси подхватит новый порт автоматически; при `npm start` открывайте сайт на новом порту |
| Сайт не открывается после `npm start`, хотя API отвечает | Выполните `npm run build` и снова запустите `npm start` |
| Интерфейс сообщает об ошибке загрузки | Откройте `/api/health` на текущем порту backend и проверьте вывод терминала |
| Исчезло избранное после смены адреса | Используйте прежний профиль браузера, имя хоста и порт: гостевые сессии привязаны к адресу сайта |

При изменении порта и отдельном запуске бота также обновите `API_BASE_URL` в `.env`.

## Подключение MAX

Этот раздел нужен для проверки бота и мини-приложения внутри MAX. Для локальной проверки сайта достаточно шагов выше.

В корневом `.env` укажите действующий `MAX_BOT_TOKEN` и `MAX_BOT_USERNAME` своего бота. Сначала запустите приложение, затем в другом терминале из корня проекта:

```sh
npm run bot
```

Для TLS-соединения с API MAX перед запуском процесса задайте `NODE_EXTRA_CA_CERTS` с путём к PEM-файлу официального корневого сертификата. В Docker сертификат подключается автоматически. Настройка серверного окружения описана в [deploy/README.md](deploy/README.md).

В MAX доступны команды `/start`, `/app` и `/help`. Для одного токена запускайте только один процесс бота: одновременный локальный и серверный long polling может конфликтовать.

Для открытия мини-приложения на телефоне сайт и API должны быть доступны по публичному HTTPS-адресу. Этот адрес необходимо сохранить в настройках мини-приложения у бота MAX. Адрес `127.0.0.1` на телефоне не ведёт на компьютер разработчика. Если бот выдан организаторами, привязку URL выполняет владелец бота.

## Docker и папка deploy

`deploy/` содержит файлы для размещения на VPS и технического воспроизведения серверного запуска:

| Файлы | Для чего нужны |
| --- | --- |
| `deploy/README.md` | Инструкция серверного запуска, обновления и восстановления |
| `deploy/production.env.example` | Шаблон `.env.production` для Docker Compose |
| `deploy/nginx-http.conf`, `deploy/nginx-https.conf` | Настройка HTTP/HTTPS и проксирования запросов в backend |
| `deploy/renew-certificate.sh`, `deploy/grantshak-cert-renew.*` | Продление сертификата по расписанию |
| `deploy/backup.sh`, `deploy/grantshak-backup.*` | Резервное копирование SQLite по расписанию |

Для локального запуска через npm выполнять скрипты из `deploy/` не требуется. Для проверки Docker пригодится шаблон окружения; конфигурация Nginx, сертификаты и systemd нужны при размещении на Linux-сервере. Файлы `Dockerfile` и `compose.yaml` находятся в корне проекта.

При проверке Docker понадобятся работающие Docker Engine и Docker Compose v2, а также заполненный `.env.production` по шаблону из `deploy/`. `npm run setup` создаёт только локальный `.env`. Compose запускает backend в production-режиме, поэтому в `.env.production` требуются `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME`, `JWT_SECRET` и `INTERNAL_API_KEY`; для локального сайта задайте `ALLOWED_ORIGINS=http://127.0.0.1:4000,http://localhost:4000`.

Для проверки сайта и API без запуска второй копии бота:

```sh
docker compose up -d --build api
docker compose ps
docker compose logs --tail=50 api
```

Откройте http://127.0.0.1:4000. Перед этим остановите локальное приложение, если оно использует тот же порт. Для остановки контейнеров:

```sh
docker compose down
```

Данные сохраняются в томе `grantshak_data`. Ключ `-v` у `docker compose down` удаляет том вместе с базой; для обычной остановки он не нужен.

Полный запуск сайта и бота, настройка HTTPS и размещение на другом VPS описаны в [deploy/README.md](deploy/README.md). В серверных конфигурациях заранее указан адрес текущего VPS; при переносе его нужно заменить на свой.
