# ГрантХаб

Мини-приложение MAX с каталогом грантов, профилем бизнеса и избранным.

## Требования

- Node.js 22.12 или новее и npm — для локального запуска.
- Docker Engine и Docker Compose v2 — для запуска в контейнерах.
- Токен бота MAX и публичный HTTPS-адрес — для работы внутри MAX.

Все команды ниже выполняются из корня репозитория.

## Локальный запуск

```sh
npm run setup
npm run install:all
npm run dev
```

`setup` создаёт `.env` с локальными настройками и случайными секретами. Существующий файл не перезаписывается.

- Интерфейс: http://127.0.0.1:5173
- Проверка API: http://127.0.0.1:4000/api/health
- Остановка: `Ctrl+C`.

При `ALLOW_DEV_AUTH=true` используется общий локальный тестовый пользователь. Бот запускается отдельно.

## Запуск собранного приложения

Остановите сервер разработки, затем выполните:

```sh
npm run build
npm start
```

Сайт и API будут доступны по адресу http://127.0.0.1:4000.

## Подключение MAX

Заполните в `.env` значения `MAX_BOT_TOKEN` и `MAX_BOT_USERNAME`. После запуска API выполните в отдельном терминале:

```sh
npm run bot
```

Команды `/start` и `/app` открывают доступ к мини-приложению, `/help` показывает справку. Для одного токена запускайте только один экземпляр бота; используется long polling.

Для открытия приложения с телефона разместите сайт и API по публичному HTTPS-адресу и укажите его в настройках мини-приложения у бота MAX. Если бот выдан организаторами, адрес привязывает владелец бота.

На публичном сервере используйте `NODE_ENV=production` и `ALLOW_DEV_AUTH=false`. Вход выполняется по данным MAX. Открытие URL в обычном браузере без этих данных покажет предложение перейти в MAX.

Для соединения с API MAX нужен доверенный корневой сертификат. В Docker он подключён автоматически. При запуске без Docker укажите путь к PEM-файлу официального сертификата через `NODE_EXTRA_CA_CERTS` перед запуском процессов Node.js.

## Docker

```sh
cp deploy/production.env.example .env.production
chmod 600 .env.production
```

Заполните `.env.production`: токен и имя бота, `ALLOWED_ORIGINS` с HTTPS-адресом приложения, а также два разных случайных значения `JWT_SECRET` и `INTERNAL_API_KEY`. Для генерации каждого секрета выполните `openssl rand -hex 48`.

```sh
docker compose up -d --build
docker compose ps
curl --fail http://127.0.0.1:4000/api/health
```

Контейнер `api` обслуживает сайт и API, `bot` обрабатывает сообщения MAX. Порт 4000 доступен только на сервере; внешний доступ настраивается через HTTPS-прокси.

Настройка VPS, HTTPS и резервного копирования: [deploy/README.md](deploy/README.md).

## Настройки

| Переменная | Назначение |
| --- | --- |
| `MAX_BOT_TOKEN` | Токен бота MAX |
| `MAX_BOT_USERNAME` | Имя бота без `@` |
| `JWT_SECRET` | Секрет сессий, не менее 32 символов |
| `INTERNAL_API_KEY` | Ключ связи бота с API, не менее 32 символов |
| `ALLOW_DEV_AUTH` | Локальный тестовый вход; на сервере `false` |
| `API_BASE_URL` | Адрес API для бота |
| `ALLOWED_ORIGINS` | Разрешённые origins через запятую |
| `DB_PATH` | Путь к SQLite; относительный путь считается от `grants-backend` |
| `NOTIFICATIONS_ENABLED` | Напоминания об избранных грантах; по умолчанию `false` |

В локальном режиме API и бот читают `.env`, в Docker — `.env.production`. Эти файлы не добавляются в Git. В репозитории хранятся только шаблоны без секретов.

## Данные

Локальная база: `grants-backend/data/grants.db`. В Docker база находится в volume `grantshak_data`. При первом запуске каталог заполняется из `grants-backend/data/grants.seed.json`.

Пользователи, профили и избранное сохраняются между запусками. Команда `docker compose down -v` удаляет volume вместе с базой — не используйте её для обычного обновления.

## Проверки

```sh
npm run check
npm test
npm run build
```

Тесты используют отдельную базу в памяти и не отправляют сообщения в MAX.

После подключения адреса в MAX проверьте `/start`, открытие приложения, поиск грантов, сохранение профиля и избранного, затем повторное открытие приложения.
