# ГрантХаб: локальное приложение + API + MAX-бот

Нужен Node.js **22 или новее** и npm. Docker-образ пока не собирается.

## Структура и границы приложения

```text
grantsHak/
├── grants/                  # Web-интерфейс, React + Vite
│   └── src/
│       ├── app/             # Подключение приложения, общие стили
│       ├── pages/           # Экраны и координация загрузки данных
│       ├── widgets/         # Навигация
│       ├── features/        # Фильтрация и действия с избранным
│       ├── entities/        # Гранты и профиль бизнеса
│       └── shared/          # UI-примитивы, HTTP-клиент, MAX Bridge, ресурсы
├── grants-backend/          # Единственный владелец данных
│   ├── src/
│   │   ├── app.ts           # Сборка Express-приложения
│   │   ├── server.ts        # Запуск HTTP-сервера и cron, остановка процесса
│   │   ├── routes/          # HTTP-контракты
│   │   ├── middleware/      # Проверка доступа
│   │   ├── services/        # Уведомления
│   │   └── scripts/         # Служебные команды
│   ├── data/               # SQLite и единственный серверный seed
│   └── test/               # Интеграционные тесты на БД в памяти
├── my-bot/
│   ├── src/bot.js          # Обработчики MAX, обращения к API
│   ├── src/index.js        # Конфигурация и запуск polling
│   └── test/               # Тесты без соединения с MAX
├── scripts/                # Общие команды настройки и разработки
├── .env.example            # Единственный шаблон серверной конфигурации
└── package.json            # Команды для всех трёх сервисов
```

Фронтенд и бот обращаются к API, но не читают SQLite напрямую. Бот не хранит отдельные анкеты или каталог. Модель профиля находится в `entities/business-profile`, а не в устаревшей форме подбора. UI использует зависимости нижних слоёв: `app → pages → widgets/features → entities → shared`.

Сервисы сохраняют собственные `package.json` и lock-файлы для воспроизводимой установки. `node_modules` и `dist` — необходимые генерируемые каталоги, а не исходники; они исключены из Git. Корень Git-репозитория расположен в `grantsHak`: он включает фронтенд `grants`, сервер `grants-backend`, бота `my-bot` и общие скрипты. История прежнего репозитория фронтенда сохранена.

## Запуск разработки

Из этой папки (там, где `grants`, `grants-backend`, `my-bot`):

```sh
npm run setup
npm run install:all
npm run dev
```

- Приложение: **http://127.0.0.1:5173**
- Проверка API: http://127.0.0.1:4000/api/health
- `Ctrl+C` останавливает оба процесса.
- `setup` создаёт `.env` с криптографически случайными локальными секретами; существующий `.env` не перезаписывает.
- Запуск разработки **не запускает MAX polling и не отправляет сообщения**.

В локальном режиме `ALLOW_DEV_AUTH=true` приложение входит под отдельным тестовым пользователем в серверной БД. Все браузеры на этом компьютере видят его общий профиль и избранное. При этом старые данные `localStorage` не импортируются и не удаляются.

## Единственный источник данных

`grants-backend/data/grants.db` — SQLite: гранты, пользователи, профили, избранное, история уведомлений. Путь можно изменить через `DB_PATH` (относительно `grants-backend`).

Если БД ещё нет/каталог пуст, начальные гранты берутся **только** из `grants-backend/data/grants.seed.json`. Существующие записи при обычном старте не обновляются из seed. `npm --prefix grants-backend run seed` — отдельная явная операция обновления грантов из серверного seed.

Фронт получает `/api/grants`, `/api/profile`, `/api/favorites`. Дублирующий JSON фронта и старый `my-bot/users.json` удалены из проекта. При недоступности API показывается ошибка, а не подставные локальные данные. ИИ-чат остаётся выключенным.

## Проверки и единый сервер без Docker

```sh
npm run build
npm run check
npm run test
npm start
```

Перед `npm start` остановите `npm run dev`, чтобы освободить порт 4000. После сборки один Node.js API-сервер отдаёт и фронт, и `/api`: **http://127.0.0.1:4000**. Это также основа будущего Docker-образа; образ сейчас не создаётся.

Тесты бэкенда используют БД в памяти и тестовые подписи MAX; тесты бота имитируют API и не отправляют сообщения. Локальная рабочая БД не затрагивается.

## Связь с MAX (следующий этап, после локальной проверки)

1. Перевыпустите ранее захардкоженный токен бота в кабинете MAX и положите новый **только** в корневой `.env`: `MAX_BOT_TOKEN`.
2. Укажите `MAX_BOT_USERNAME`. Бот и API читают одну конфигурацию, поэтому проверяют один и тот же токен.
3. Поднимите API, затем отдельно `npm run bot`. Бот использует long polling: нужен один экземпляр, без одновременно подключённого webhook. `/start` и `/app` регистрируют пользователя в API и показывают кнопку мини-приложения. Анкета заполняется в приложении; отдельного JSON-хранилища бота больше нет.
4. Для открытия настоящего мини-приложения на телефоне нужен публично доступный **HTTPS-адрес**. `localhost` компьютера недоступен клиенту MAX на телефоне. Когда появится размещение, URL указывается в настройках мини-приложения бота в кабинете MAX. Сейчас домен/развёртывание не настраиваются.
5. Frontend сохраняет исходный `WebAppData` до изменения hash-роута, подключает MAX Bridge и отправляет данные на `/api/auth/max`. Сервер проверяет HMAC, срок действия, дубликаты параметров и пользователя; затем выдаёт JWT. JWT хранится только в памяти вкладки. Неподписанный `initDataUnsafe` для авторизации не используется.
6. Перед production: `NODE_ENV=production`, `ALLOW_DEV_AUTH=false`, `HOST=0.0.0.0`, новые `JWT_SECRET`/`INTERNAL_API_KEY`, постоянный диск для SQLite, HTTPS reverse proxy. Если бот на другом хосте, `API_BASE_URL` должен быть HTTPS. `ALLOWED_ORIGINS` — явный список origins для раздельного размещения; проще оставить фронт и API на одном origin.
7. Напоминания включаются отдельно: `NOTIFICATIONS_ENABLED=true`. Они отправляются только положительным MAX user ID, которые начали диалог с ботом, и только по избранному из БД. Тестовый локальный пользователь исключён. Хранится дедупликация по гранту и его дедлайну. Запускайте только один экземпляр API с cron для этой SQLite-БД.

Локальная авторизация запрещена при `NODE_ENV=production` и при bind не на loopback; сервер проверяет также Host. Тестовые JWT не должны использоваться в production — меняйте секреты.

MAX API использует `https://platform-api2.max.ru`. Если окружение требует дополнительный доверенный CA, настройте `NODE_EXTRA_CA_CERTS` на доверенный сертификат, полученный из официального источника. Не отключайте TLS-проверку.

Документация: [MAX Bridge](https://dev.max.ru/docs/webapps/bridge), [валидация подписи](https://dev.max.ru/docs/webapps/validation), [подключение мини-приложения](https://dev.max.ru/help/miniapps), [Bot API](https://dev.max.ru/docs-api).

## Передача организаторам позже

Передавать нужно весь репозиторий: все три папки и корневые `package.json`, `scripts`, `.env.example`. Не включайте `.env`, `node_modules`, `users.json` и рабочую БД с персональными данными. Секреты передаются отдельно безопасным способом. Для будущего контейнера SQLite должна лежать в постоянном volume; frontend собирается из `grants`, бот запускается отдельным процессом из того же проекта. Dockerfile/образ пока не создавались.
